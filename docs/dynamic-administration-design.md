# Dynamic provider/model administration: bounded design proposal

Date: 2026-09-16. Status: implemented after targeted Design Gate PASS WITH FINDINGS; final Mentor Quality Gate PASS. Operational evidence limitations are recorded separately. Companion: [gap analysis](dynamic-administration-gap-analysis.md). No production changes are authorized by this document alone; Mentor Design Gate must pass.

## Scope and proposed security decision

Implement one in-process Java registry, additive gRPC administration, Flask Admin Console, OpenAI/Google/Anthropic structured-image adapters, and a generic nine-combination harness. No database, routing/fallback, domain semantics, multi-image input, or Video Inventory changes.

**Architect decision (continuation):** Administration is a privileged authenticated boundary. Every Admin RPC uses a server interceptor validating a Human-provisioned external bearer token; absent, malformed or invalid credentials yield UNAUTHENTICATED. Never log auth metadata. Keep a separate Admin listener, default explicitly bound to numeric loopback. Both inference and Admin listeners require configured TLS certificate/private key for any non-loopback bind; fail startup on insecure remote configuration. Explicit loopback may omit TLS but never Admin authentication. Remote Admin over server-authenticated TLS and bearer credentials is supported; no OAuth/OIDC/mTLS is needed. The Console remains explicitly loopback-bound with Host/Origin/CSRF controls; its Admin token stays server-side and its gRPC client uses TLS for remote endpoints. No transport downgrade or trust-all option.

External settings define numeric bind addresses, ports, TLS certificate/key and trusted client CA file paths. Bind validation examines the actual InetAddress used by the listener and rejects unspecified/wildcard remote plaintext. TLS material and Admin token require restart to replace; ordinary provider credentials support explicit authenticated reload. Never create real credentials in Codex. Missing Admin token disables startup of the management-enabled server rather than creating an unauthenticated mode.

Provider credentials remain Human-controlled external files. Credential replacement through UI/gRPC is not supported (conditional in task); authenticated status/reload permits Human replacement without inference restart. No API returns secret paths or values. Use external configuration/secret storage, never hard-coded credentials.

The Google correction is mandatory in this increment: use `x-goog-api-key` headers, never query keys. All text/stream/embedding errors must become sanitized provider errors with stable code/provider/HTTP status; no raw exception causes, complete HTTP responses, sensitive URLs or headers cross service/log boundaries. Synthetic-marker regression tests assert absence in request URLs, captured logs, exception messages/causes and returned service errors. TLS/bearer tests cover missing, invalid, valid credentials and rejection of remote plaintext for both listeners.

## Registry and persistence

Use existing Jackson for a versioned external JSON document at a required `XLM_CONFIG_DIR`, outside the checkout/classpath. Store schema version, monotonically increasing revision, providers keyed by stable ID, models keyed by (provider, model), and defaults keyed by `chat`, `structured_image`, `embedding`. Provider entries contain enabled state and typed allowlisted non-secret settings; capability metadata is constrained by adapter support. Model entries contain ID, provider, optional display name, enabled state, and a nonempty supported capability set. No arbitrary secret/config map is echoed.

A single writer lock validates the complete candidate state, prepares replacement adapters, writes a same-directory temporary file, flushes it, and atomically replaces the registry. Only then publish one immutable runtime snapshot with its adapter instances. Readers take one snapshot for the entire request; in-flight requests complete with their original snapshot. Concurrent updates require `expected_revision`; stale writers receive ABORTED. Hold a process file lock to disallow two XLM processes sharing a registry. Fail closed on corruption, invalid schema/revision, lock failure, or unsupported atomic replacement. No silent reset to defaults. Preserve old state on pre-commit write failure; test crash before/after replacement and restart. Document filesystem power-loss durability limits separately from process-restart guarantees.

Seed once from a non-secret catalog and explicitly configured legacy model defaults/vision list, then registry becomes the sole catalog authority. Do not repeatedly reimport defaults over administrator edits. Remove class-owned model allowlists. Unknown models and unsupported model capabilities fail validation. No remote model auto-discovery or ranking.

Credentials are loaded separately into internal runtime objects from fixed provider-specific protected files outside checkout; never persisted in registry JSON. Human owns directory/file access protection. Reject blank/template credentials as absent. Credential reload validates all input before publishing a new snapshot; report only presence, never validity claims. No watches, secret-writing endpoint, or complex hot reload. Config/admin listener locations and auth-file provisioning are startup settings; provider/model/default/settings and credential reload affect future requests immediately.

Supported mutable provider settings are bounded numeric timeout/output-token values and existing required non-secret project/location fields where applicable. Endpoint origins/auth header rules are adapter-owned; arbitrary endpoints, query credentials, URL userinfo, redirects, and unknown settings are rejected to prevent credential exfiltration. Local mock endpoints must be injected only through tests, not a production bypass. No secrets in validation errors, registry status, exceptions, logs, or persisted evidence. Fix legacy Google URL-key/error propagation and sanitize upstream failure details before real calls. Exclude `config.properties` from Maven resources; do not copy legacy secrets into new files automatically.

## Additive protobuf/Admin API

Add separate `XlmAdminService` and new messages. All read and write methods require Admin auth. Proposed operations: ListProviders/GetProvider/SetProviderEnabled; ListModels with optional provider/capability filters; UpsertModel/SetModelEnabled; GetDefaults/SetDefault; GetProviderConfiguration/UpdateProviderConfiguration; ReloadCredentials; GetStatus. Mutation requests carry expected revision, and return the committed revision. Status contains version, registry schema/revision, readiness, and capability/default summaries, without filesystem paths or secret-bearing diagnostics.

Bound identifiers, model display names, config sizes, and record counts; reject unknown enums, duplicate identities, mismatched provider IDs, unknown config keys, and unsupported capabilities. Use INVALID_ARGUMENT, NOT_FOUND, FAILED_PRECONDITION, ABORTED, UNAUTHENTICATED, and safe INTERNAL errors consistently. A missing credential is distinct from provider/model enablement; discovery may list enabled but uncredentialed providers, while invocation fails safely.

Preserve all old RPC paths, field tags and enum numbers. Legacy discovery reads registry metadata through the existing response shape. Add explicit `provider` and `model` fields to EmbeddingRequest with unused tags; preserve legacy model-parameter map interpretation where defined. Add structured-image error enum values for disabled provider/model and incompatible capability. Existing explicit image requests remain wire compatible. Defaults expand formerly-invalid omitted selection behavior without changing valid explicit requests.

## Selection and state semantics

1. Full explicit pair always wins, checked against one snapshot (existence, enabled state, provider and model capability).
2. For legacy chat/embedding only, an explicit model without provider uses the client's capability preference if present. The current service accepts this legacy request shape; add a regression for it. The stock Java sample supplies both fields. Validate the pair normally. Without that preference, reject incomplete selection; never search providers for a matching model. Structured-image model-only requests remain invalid.
3. Explicit provider without model uses the capability default only if it names that provider; otherwise reject as incomplete. Never change the explicit provider.
4. Without explicit provider, legacy chat/embedding client preferences take precedence over global defaults. Resolve their model from a compatible requested model or the provider's migrated capability default; no cross-provider substitution.
5. With no explicit selection or legacy preference, use the global capability default. Missing/invalid defaults fail; never choose another model.

Keep provider-specific migrated default IDs in registry for legacy preference behavior, separate from the single global default pair per capability. These migration references must name existing models but do not block disabling or capability changes; legacy invocation validates their current capability/state and fails safely if no longer usable. Only global defaults block disabling or incompatible capability changes until explicitly changed or cleared. Clearing a global default is an explicit Admin operation. Existing client preferences may become disabled; requests then fail, they do not fall through to global defaults. `setPreferredProviders` validates the full update atomically, stores IDs, and cannot bypass registry enablement. Registration remains ephemeral and is repeated by the harness after restart.

## Adapters and Console

Extend OpenAI to accept registry-selected models while preserving bounded HTTP/1.1 image behavior. Add Google generateContent image bytes plus JSON schema configuration using header authentication; add Anthropic Messages base64 image plus `output_config.format` JSON schema. Anthropic only advertises implemented capabilities. Keep all payload construction, response parsing, refusal/truncation handling, HTTP mapping and provider-returned model identity inside adapters. Preserve image/request bounds and safe normalized errors. Treat syntactically valid object JSON separately from schema acceptance; harness validates the common schema independently. Unsupported provider schema features remain explicit errors, never prompt-only fallback.

Extend current Flask app/templates with Providers, Models, Defaults, and Status/Test views. Browser calls bounded same-origin routes; those routes call Admin RPCs rather than reading registry/secret files. Test routes call inference gRPC with selected explicit IDs or deliberately omitted default selection. Display requested and returned identities, normalized status/error/result and measured latency as text. No duplicate configuration rules in UI; server validation is authoritative. Preserve existing Chat UI flows and tokens; remove raw error/token logging where it could disclose secret-bearing upstream diagnostics.

The proposed local Console assumes trusted local users/processes and is not a multi-user authorization boundary. Enforce exact configured loopback Host and Origin allowlists, including WebSocket handshakes; reject untrusted Host before rendering any CSRF token to prevent DNS rebinding. Require CSRF on mutations; do not enable wildcard CORS or trust forwarded-host headers. Test hostile Host/Origin, missing/wrong token, and cross-origin WebSocket attempts. A hostile local-user threat model requires a revised UI authentication/transport design and Architect approval.
