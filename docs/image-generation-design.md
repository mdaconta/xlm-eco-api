Status: Mentor Design Gate PASS WITH FINDINGS; both recommendations incorporated below. Scope includes implementation, meaningful Java/Python coverage hardening, and public documentation reconciliation. No editing, media storage, automatic routing, or remote publication.

Design findings: existing RPC selection semantics remain unchanged, including provider-only selection matching a default and legacy model-only preferences. ## Gap analysis

The registry has independent string capabilities (`chat`, `structured_image`, `embedding`) and atomic persistence; no generation capability exists. Structured image analysis returns JSON, not pixels. The Chat composer has a separate large analysis panel and fixed startup text selection. Provider discovery is provider-level; model listing currently requires Admin credentials. Java has JUnit tests but no JaCoCo gate; Python uses unittest without a coverage gate. Existing historical design records must remain distinguishable from current behavior.

## Proposed contract

Add `image_generation` without renaming existing capabilities. Add unary `generateImage(ImageGenerationRequest)`; the RPC itself is the explicit image operation, while existing chat RPCs remain explicit text operations. Request: client_id, prompt, provider, model. Response: success, output_type (GENERATED_IMAGE on success), singular generated image (MIME and inline bytes), provider, model, server-generated request_id, normalized error. Reuse the established StructuredImageError/error-code wire type with documentation explaining its shared use; do not renumber existing tags. No speculative options. Prompt <=64 KiB UTF-8, IDs <=128 characters, exactly one result <=3 MiB. This preserves default 4 MiB gRPC response bounds. Validate decoded image format and dimensions (<=4096 per side and <=16 megapixels), rejecting malformed content before publishing it. No returned provider URLs.

Add read-only inference `listModels` with registration, optional provider/capability filters, returning catalog model metadata and effective enabled state without Admin secrets or settings. Admin RPC remains the sole mutation boundary. Both discovery and execution use registry capabilities; explicit selection wins, omitted IDs use the capability default, model-only selection fails and provider-only selection requires the same provider default, no fallback. Existing registries are never reseeded or assigned a generation default on upgrade.

## Providers and persistence

Typed `ImageGenerationProvider` input/result interface; adapters own HTTP request/response mapping. OpenAI Images endpoint requests one PNG, 1024x1024, fixed low quality; initial seed `gpt-image-1` advertises generation only. Google generateContent requests TEXT/IMAGE and extracts exactly one non-thought inline image; initial seed `gemini-2.5-flash-image` advertises generation only. Its provider-documented image input is not XLM structured JSON support. Existing configured text/vision models do not gain generation automatically. Existing installations add generation models explicitly through Admin. Registry validation constrains capabilities by implemented provider support; remote model availability remains an operator responsibility, not inferred from catalog membership. Anthropic/Grok/Ollama do not advertise generation in this slice.

Use existing trusted endpoint/authentication patterns, no redirects, no retry or URL fetch, bounded call timeout and <=4 MiB + 64 KiB JSON transport envelope (3 MiB base64 plus overhead). Normalize quota/authentication/rate/timeout/network/refusal/malformed failures without upstream exception/body leakage. Google generation always needs the explicit API key, not legacy ADC bypass. New HTTP limits must not enlarge existing structured JSON limits.

Official contracts checked: [OpenAI Images](https://developers.openai.com/api/reference/resources/images/methods/generate), [Google generateContent images](https://ai.google.dev/gemini-api/docs/generate-content/image-generation), [Google model capability limits](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash-image). Provider documentation does not establish remote verification.

## Chat

Catalog provider/model selector, explicit Generate image checkbox, suggestion button for simple imperative generation phrases. Suggestions never change mode or selected model automatically; ignoring/dismissing is an override. False-positive informational prompts stay text. Compact `+`, shared prompt, Send row; one image chip/thumbnail with remove; advanced JSON schema collapses under attachment controls. Attachment means structured analysis; attachment plus generation is blocked (editing is outside scope). Unsupported selected capability blocks submission; server independently rejects it. Inline generated image, prompt and provenance remain in ordered transcript entries. Use safe DOM text and bounded blob URLs with cleanup; track text request/session events so responses cannot land in another request/browser. Preserve Host/Origin/CSRF/TLS boundaries. No raw upstream error strings in browser.
